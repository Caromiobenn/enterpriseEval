# enterpriseEval 自主实验完成报告

2026-09-19。当前方向保持**纯文本基础模型评测方法**，不做多模态。核心依据已收紧到正式论文和官方技术实践；新近且缺乏验证的预印本不再作为方案成立的前提。主要问题是评测是否测准、条件变化后是否可比，以及哪些证据可以低成本复用。

今天已确认方案可在现有双 RTX4090 上运行，并得到有原始轨迹支持的正、负结果。它仍是两个合成业务家族的研究原型，不是大型基准复现或通用长程能力证明。

## 完成范围

本轮新增 **292 次真实模型 episode**：4 次接口 probe、24 次开发比较、64 次主矩阵、72 次迁移对照、32 次规模扩展、64 次新参数验证、32 次输出预算诊断。每个 episode 包含多次模型/工具调用，不能把运行数量当作独立任务数量。此前 16 次 pilot 单独保留，合计 308 份历史模型运行记录。

所有计划单元均有结果，无缺失。失败、截断、超预算和 HTTP 错误保留在分母中。主要阶段 288 份记录完成逐步工具重放，返回值和终态全部匹配；4 次旧接口 probe 按原协议保留。两次上下文 HTTP 错误没有完整 usage，未当作零成本。28 项自动测试通过。

环境为 Qwen2.5-7B/14B-Instruct-AWQ、vLLM 0.7.3、两张 RTX4090，每个模型独占一张卡并串行执行。完整运行条件见 [runtime-info](../artifacts/runtime-info.json)。本轮没有训练或修改模型权重。

## 结果一：更严格的 grader 也可能测错

旧 v1 判分要求成功写操作数量精确等于最短参考流程。实际轨迹中，模型有时对已正确关联的支付多做一次无害关联，终态仍正确，却被数量约束拒绝。修订规则保留必要操作证据、无重复提交和业务终态保护，将这种冗余单独记录。

| 固定矩阵 | 模型 | 旧规则 | 修订规则 |
|---|---|---:|---:|
| 主矩阵 | 7B | 16/32 | 22/32 |
| 主矩阵 | 14B | 28/32 | 28/32 |
| 新参数验证 | 7B | 17/32 | 23/32 |
| 新参数验证 | 14B | 25/32 | 25/32 |

主集与新参数集各有 6 份正确终态被旧数量规则拒绝。修订发生在检查主集后，明确属于探索性合同修订；没有外部专家 gold 标注。新种子仍属于相同两类业务，不能当作跨域验证。旧规则、分数和原始产物完整保留。

更值得面试展示的是 8 个预先按条件选定的提示对照单元：

| 判分口径 | 恢复提示，原条件 | 最简提示，实际重跑 |
|---|---:|---:|
| 旧 v1 | 6/8 | 7/8 |
| 修订 v2-outcome | 8/8 | 7/8 |

**同一对提示的比较方向因判分规则而翻转。** 这说明先验证尺子比直接优化分数重要；8 个相关单元不足以给出提示优劣的统计结论。配对 ID 与所有标签见 [final-results.json](../artifacts/final-results.json)。

## 结果二：规模变大后的低分包含输出预算影响

将固定锚点的规模 4 条件扩展为规模 8，原 512-token 单次输出上限下为 0/32；其中 23 次输出截断、8 次正常结束但任务失败、1 次上下文 HTTP 错误。

随后只把单次输出上限改为 2048，保持任务、模型、提示、模型/工具调用次数上限和采样条件不变，另跑 32 次配对诊断：

| 指标 | 512 上限 | 2048 上限 |
|---|---:|---:|
| 任务成功 | 0/32 | 6/32 |
| 输出截断 | 23/32 | 0/32 |
| HTTP 上下文错误 | 1/32 | 1/32 |

6 次成功均来自 14B 的离职交接；该子组为 6/8。7B 两类任务及 14B 发票核对仍未成功，另有工具预算、模型调用预算和解析问题。提高输出上限并未解决全部问题，也增加了实际 token 使用。该对照是观察失败后开展的诊断，总 token 预算没有匹配，不能包装成模型能力提升或公平成本下的性能提升。

规模变化同时影响上下文、操作数和组合负担，**不能用这次 0 分直接断言长程规划能力不足**。

## 结果三：版本迁移闭环真实执行

- 对 64 份主矩阵产物重判，没有新增模型调用，保存的同产物判分可重建。
- 另执行 64 次原条件重跑，历史 v1 成功标签全部与原记录一致；消耗 698,116 输入 tokens 和 43,541 输出 tokens，共 **741,657 tokens**。
- 对提示发生变化的 8 个单元实际重跑；扩大任务规模、改变输出预算也都新建计划并执行，没有拿旧轨迹替代。
- 最终在本机读取、校验、工具重放并重判 288 份主要记录，约 2.89 秒；其中判分内核约 0.095 秒。此计时只描述本次实现，不与多 GPU 累计 episode 秒数混算加速比。

这证明的是**保存产物充分、grader 私有且不影响 actor**时的复用条件，不是“所有评测都可以免费更新”。三分法直接参考 [Terminal-Bench/Harbor 官方 Continuous Benchmarks](https://www.tbench.ai/news/continuous-benchmarks)，不宣称原创算法。
