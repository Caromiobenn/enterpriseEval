# 实验方法与证据边界

本项目研究纯文本基础模型评测中的协议敏感性、判分有效性及版本更新成本。两个合成业务环境提供可控状态与可重放轨迹；它们不是生产应用，也不是完整 AppWorld 或 τ-bench 复现。核心一手资料及具体采用范围见 [FOUNDATIONS](FOUNDATIONS.md)。

## 测量单位

- **业务家族**：离职交接、发票核对，共两个。改实体 ID、金额或记录数不会产生新的独立业务家族。
- **案例条件**：家族、实体种子、规模、故障开关。故障为第二次成功写入后响应丢失，状态已经提交；记录故障实际是否触发。
- **模型运行**：案例条件 × 模型 × 提示/调用协议 × 采样种子。相同案例重复运行不当作独立语义题。
- **模型条件**：Qwen2.5-7B/14B-Instruct-AWQ，各用一张 RTX4090。本轮观察不能推广到未量化模型或整个 Qwen 系列。

默认每次最多 24 次模型调用、40 次工具调用、每次响应 512 tokens、240 秒；temperature=0.2、top_p=0.9。两个模型在独立 GPU 上各串行执行任务。同一批次冻结模型文件摘要、环境/协议源码、提示、工具 schema、预算和完整计划；记录原始响应、工具事件、最终状态及 usage。

## 开发、锚点与扩展

1. 原始 v0 pilot 的两个协议各 8 次，仅用于工程诊断，不拼接排名。
2. v1 JSON probe 4 次全部失败，保留失败接口设计。v2 使用按工具区分的 JSON schema，并明确操作级 request_id。
3. v2 开发集 24 次：一个实体种子、规模 2、两个家族、clean/fault、两个模型、三种协议。native-recovery 7/8，native-minimal 与 JSON-recovery 各 6/8。按开发观察选前者，不称显著更优。
4. 主矩阵 64 次：两个家族 × 两个新实体种子 × 两个规模 × 两种故障 × 两个模型 × 两次重复。规模在种子内交叉。这里的 holdout 只指实体参数，没有留出业务家族。
5. 扩展保留上述锚点，另将规模 4 的 32 个条件对应扩展到规模 8；改变任务可见条件，必须新运行。每个新案例有两种合法顺序的参考解，并核对预算可达。触发条件来自开发集小规模表现，但规则在看到开发结果后制定，**不是预注册规则**。
6. 发现 grader 过严后冻结独立私有修订，另用种子 77/99 验证。新种子仍不能消除两个家族的外部效度限制。

规模增大同时改变上下文内容、操作数和组合负担，因此不能将差异单独归因为长程规划能力。参考解预算可达也不代表模型探索时预算充裕。失败、截断、超预算和 HTTP 错误均留在分母中，另外诊断。

## 判分修订：严格不等于有效

历史 v0 grader 只检查目标完成，刻意省略旁路影响；它是受控缺陷，不是外部 benchmark 漏洞。历史 v1 加入完整业务终态、无重复写入和精确操作数量。

检查主集后发现，精确数量将“给已经关联正确的支付再做一次同样关联”的轨迹拒绝，即使该操作没有改变业务状态。这类冗余应与错误退款等结果错误区分。新的 `v2-outcome` 保留必要操作证据、完整终态保护及禁止重复已提交操作，但允许一次无害的初始正确关联，另计冗余数。

这是一项公开的、看过主集后的合同解释与探索性修订。并未获得外部专家 gold labels，不能仅以分数上升证明新 grader 正确。合法替代解、故意破坏终态/必要证据/重复操作的反例以及新参数运行用于增加验证。全部旧 grader、分数和产物保留，不能回写成“最初就采用新规则”。

真实模型轨迹中的变化与人工构造 mutant 测试分表。原先 v1 在有限构造测试中没有误拒绝，并未阻止它在真实轨迹上出现过度约束；这也是构造测试覆盖面的具体局限。

## reuse / regrade / rerun

| 变化 | 操作 | 约束 |
|---|---|---|
| 仅报告元数据变化 | reuse | 原始产物完整且哈希匹配 |
| 仅私有、运行后 grader 变化 | regrade | 保存了新规则所需的状态/轨迹；原 grader 不向 actor 反馈 |
| 模型、任务、工具、提示、预算、采样条件变化 | rerun | 保留旧证据，创建新计划 |
| 产物缺失或 grader 曾影响 actor | rerun | 不把不充分证据当可复用证据 |

v3 对主集全部 64 份产物做确定性重判，再运行 64 次相同条件的新执行作成本/重复性对照；另外对事先按条件选择的 8 个单元改提示并实际重跑。相同产物重判必须一致；新的随机执行不要求逐条一致。

成本分别报告额外模型调用、prompt/completion tokens、重判 CPU/墙钟时间与完整读取校验/工具重放耗时。多 GPU 的累计 episode 秒数不是端到端墙钟时间，不能混算加速倍数。本地推理未调用付费 API，但使用用户现有租赁算力不等于经济成本为零。

## 可以与不可以得出的结论

可以证明：这些具体工作流在现有双卡上能跑；计划与产物可对账；工具事件可重放；私有判分变化可在充分产物上零新增推理地重算；某些失败来自协议或判分而非单纯模型能力。

不能证明：广泛企业泛化、通用长程能力、动态挑战生成的普遍有效性、统计稳定的模型排名、子集可替代完整基准。两个业务根不足以支持跨域置信推断；因此主报告给条件计数和配对观察，不用将重复运行视为独立任务的显著性检验。

下一阶段先接入冻结官方版本的 AppWorld 或 τ 系列**纯文本**子域，核验参考解、用户模拟器偏差和环境版本；再扩展语义家族和人工复核。历史 τ-bench 仓库已提示任务过时，应明确版本或使用维护后的任务，不能把旧任务结果当当前官方榜单。
