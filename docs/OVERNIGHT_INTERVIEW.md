# 夜间实验答辩补充（仅使用已完成证据）

## 90 秒介绍

我研究的是工具型基础模型评测中的判分有效性和可复现性。已有实验发现，固定参考操作数会误拒合法替代解，甚至改变提示策略的比较方向。为避免继续在调试过的任务上证明自己，我把已有任务留作开发，新增发布和订单履约两类前瞻留出任务，固定环境和预算，只注入一次“写入已提交、响应却丢失”的故障，并交叉比较恢复提示。

目前 DeepSeek 两模型完成 128 次验证，128 条轨迹逐步回放一致，成功 127 次。这反而说明短合成任务接近能力上限，不能靠增加重复次数证明广泛泛化。我先对预选 16 条匿名轨迹写下判断，再看自动分数，同时保留模型审查不是人工金标的限制。唯一失败的终态正确，但违反了禁止重复提交的过程要求；进一步审计还发现主判分没有覆盖读前状态与最后验证，我另做辅助审计并保留原始分数。本地两个模型另完成 512 次验证，成功 58 次。外部 AppWorld 覆盖 80 个不重叠任务前缀、1,765 次运行，当前结构化 actor 全部未成功。14B 65 对协议比较中截断从 50 降到 1，但 tokens 从 154 万增到 677 万，任务仍零成功，因此我没有把格式改善包装成能力提升。

## 合成任务为什么仍然有价值？

它可以精确控制故障时机、初态和业务不变量，让“响应丢失是否增加失败”成为可检验的问题。它的代价是生态代表性有限，所以需要外部任务补充。控制性和代表性是两类证据，不能用合成成功率替代外部效度。

## 127/128 是否证明故障恢复已经解决？

不能。只有两个语义任务族，而且显式要求读状态并给出了重试提示；模型可能通过这个特定环境，却不能迁移到未知工具、长依赖或信息不完整情境。当前能支持的是在这组冻结条件下近乎满分，而不是“解决企业 Agent 可靠性”。

## 增加到数百次运行，信息量增加在哪里？

独立任务覆盖、重复稳定性、模型条件和故障处理是不同维度。相同任务重复八次有助于看到采样波动，但不增加八个语义任务。外部分析先对同任务相同重复编号配对，在任务内汇总，再按任务做宏平均；不能把每次重复当独立样本缩窄置信区间。

## 为什么一处冗余操作可以接受，另一处重复提交却失败？

看事先定义的任务合同。白天实验中，对已正确关联记录的无害操作没有违反要求，固定操作数规则却误拒；新任务明确禁止用新请求编号重复提交，所以再次审批即使不改变布尔状态，也违反过程约束。库存任务更直接：重复预留真的多扣库存。不能根据最终分数高低决定是否接受。

## 自动回放一致是否证明 grader 正确？

回放证明记录与实现一致，不能证明实现符合全部任务要求。还需要检查合法替代解、构造错误产物、阅读真实轨迹，并寻找判分遗漏。此次辅助审计发现“读初态、验证终态”不在主判分范围，正说明回放、单元测试和语义审查各有边界。

## 你的盲审到底独立到什么程度？

审查时隐藏模型、系统提示和自动标签；按冻结规则选择样本，先提交判断再解盲。审查者仍是参与设计的 Codex，知道任务逻辑，轨迹中的超时也会暴露故障线索。因此叫模型与标签匿名审查，不能叫独立人工专家金标或完全双盲。16 条 API 样本都成功，也不能据此估计错误漏判率。

## Qwen 与 DeepSeek 的差异能归因于模型权重吗？

不能做这样的单因素归因。它们还不同于模型规模、量化、服务端实现和可能变化的 API 别名。共同任务和预算让结果可描述地比较，但不能把所有差异归因于权重。两种提示或故障的配对是在同模型内解释，API 不支持的 seed 不伪造为固定种子。

## AppWorld 是否是完整复现？

不是。实际包、数据版本和官方判分可以核验，但当前只选官方纯文本子集，并使用结构化 API actor，而非官方任意代码生成 agent。这个限制必须和任务覆盖、模型版本一起报告，不能拿子集分数直接对比排行榜。

## 如果外部基准分数很低，项目是否失败？

需要先区分环境或桥接错误、输出截断、模型错误和判分异常。开发任务用于确认运行与官方判分流程；正式任务失败保留在结果中，不用测试集继续调提示直到过关。如果合成任务满分而外部任务失败，这能揭示现有测量工具的能力覆盖不足，但仍需更多证据才能归因到某个能力。

## 哪些内容现在不能写进简历？

v10 的 539 条未启动计划、完整 GPU 满载时长、独立人工标注、广泛统计显著性、模型权重提升、完整论文复现，以及未经账单支持的实际节省比例。已完成的 2,405 次新增验证可写，但必须区分任务数与重复次数。

## 外部全零为什么还值得写？

价值在于可复现的失败诊断、对照设计和没有隐藏负结果，不在于跑得多。两个 train 参考解直接执行与关闭后判分均通过；桥接回放 5 调用任务通过，145 调用任务撞上 100 次环境执行上限。说明桥接具有可成功路径，也说明预算限制会压低分数。不能把外部全零直接当作模型能力归因完成。

## 下一步还会继续增加重复吗？

不优先。应先查明标准 actor、预算与当前结构化协议的差异，用开发任务验证修复，再冻结新的未观察任务；增加人工复核。对于当前全零结果，更多相同重复不足以证明等效，也不能替代有效的任务难度范围。
