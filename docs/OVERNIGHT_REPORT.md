## 判分可信度

640/640 合成验证轨迹逐步回放一致；最终再次运行回放校验通过。14 项确定性检查覆盖合法顺序、同请求 ID 重试、不完整任务、副作用与重复提交。两批预选的 **32 条匿名轨迹**先保存 Codex 判断再解盲，与自动主标签 32/32 一致，其中 18 条成功、14 条失败。

这不是独立人工金标：审核模型知道环境设计，超时可暴露故障条件，样本有限。API 的 16 条审核样本均成功，不能由此估计漏判率。标签提交为 API `e314273`、本地首批 `f5acba3` 和完整 `7f3daa6`，均早于各自解盲。

主判分覆盖全状态与唯一提交，但漏掉读取及最终观察义务。保留冻结主成绩，另列事后辅助检查：API 128/128、本地 409/512 同时满足两项时序观察条件；本地 58 条主成功中 56 条满足。**发现覆盖缺口比宣布判分“绝对正确”更可信。**

DeepSeek 唯一失败为同一安全审批以新请求 ID 重复提交：布尔终态正确，但违反预先明确的过程合同；未观察到业务状态损害。本地 B06 则出现实际重复扣库存，说明只看订单已发货会漏掉副作用。二者不能混称同一种失败。

## 受控复杂度与开发验证隔离

合成配对只改变首次成功写入后是否丢失响应，初态、依赖、工具和预算一致；提示因素单独交叉。故障条件不代表一定触发故障：14B 履约 recovery 条件仅 9/32 实际触发，主成绩仍按全部 32 条报告，不能只选触发成功的运行。

v8 结果用于形成 v9 提示假设后，v8 全部任务前缀退出独立验证范围；v9 使用其余 40 个前缀。v10 使用不重叠 challenge 前缀。官方 train 的两个任务用于开发和参考控制，未混入验证。每批冻结 actor、计划及哈希，后续分析器更新未改写既有 actor。

## 外部结果与协议成本

全部外部任务仍为零成功，说明当前配置尚未获得有效完成能力。不能据此断言模型在标准 AppWorld 上必然零分：这里是 **三工具结构化 API actor、AWQ 模型、40 次请求、1,024 输出 tokens、100 次环境执行**，与官方代码 agent 不同。

两个官方 train 参考解在直接执行及关闭后判分均通过。经同一结构化桥接器回放，5 调用参考解通过；145 调用参考解触及冻结的 100 执行上限而失败。正控制说明接口存在可成功路径，同时揭示预算限制，不能证明所有验证失败都来自模型。

v9 每个模型每种提示各 320 次，均零成功；显式 discovery guidance 没有带来任务成功。不能把零差异的退化 bootstrap 区间当成等效性证据。

v10 的匹配诊断如下，成对比较相同任务、模型与重复编号：

| 模型 | 完整匹配对 | native 截断 | constrained JSON 截断 | native tokens | JSON tokens |
|---|---:|---:|---:|---:|---:|
| 7B AWQ | 49 | 15/49 | 0/49 | 4,802,057 | 10,505,279 |
| 14B AWQ | 65 | 50/65 | 1/65 | 1,539,394 | 6,770,540 |

截断减少，但任务仍未成功，更多运行转为调用预算耗尽，实际 tokens 增加。JSON 语法、提示及观察消息序列化共同变化，因此这是**协议组合比较**，不是约束解码单变量因果结论；相同上限也不是相同实际成本。截止导致重复次数不齐，仅对完整匹配对比较，不将 229 条全部强行配对。
